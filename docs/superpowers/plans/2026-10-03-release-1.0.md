# Solar Odyssey 1.0 Implementation Plan

**Execution:** Direct implementation in the current working tree. The user explicitly prohibits subagents and authorizes implementation, verification, packaging, commits, and release publication without routine approval.

**Goal:** Deliver an installable, verified scientific sandbox with a clear launch experience and accurate engineering claims.

**Architecture:** Preserve the existing simulation, presentation, science, and renderer owners. Establish explicit boundaries for accepted simulation time, menu/session state, runtime paths, color space, and distribution assets rather than adding parallel authorities.

**Tech stack:** C++17, OpenGL 4.5, GLFW, Dear ImGui, OpenAL, CMake/Ninja, Windows.

## Constraints and review focus

- Preserve all valid uncommitted work and the sandbox direction; no missions, currency, unlocks, or achievements.
- Preserve numerical roots and analytic live-parent moons, safe imagery, and save compatibility.
- Exercise failed writes, tool persistence exclusions, partial startup, GPU pressure, and multiple GL contexts.
- Exercise high-speed/dropped simulation time, mode changes, pause, and continuation without jumps.
- Exercise arbitrary working directories and clean staged/installed layouts with no developer DLL paths.
- Inspect actual screenshots; do not infer visual correctness from compilation.
- Publish only after tests, runtime checks, asset/license review, and artifact inspection.

## Work sequence

- [x] Foundation: configure `build-release` with `-DCMAKE_BUILD_TYPE=Release`; build; run CTest with source shader working directory; diagnose and fix failures in Tasks 1–3.
- [x] Simulation: trace `SimulationController`, `NBodySimulation`, analytic phase and saved continuation; add clock/mode-transition regression tests; fix accepted-time and switching authority.
- [x] Data: compare `planet_data` and canonical metadata against NASA/JPL primary sources; correct masses, temperatures, atmosphere semantics and missing-value presentation; test the roster and science eligibility.
- [x] Rendering: test post-disabled output/capture ownership, remove undefined shader edges, establish color/data texture formats and single output transfer; inspect planets, exotic objects, and captures.
- [x] Session shell: add normal-launch menu and pause-owned settings, deterministic ESC/cursor/input gating, fresh/continue semantics and progress confirmation; preserve tool bypass and safe persistence.
- [x] Presentation: restrained toasts and HUD, generic label collision policy, independent Classic/Scientific starfields, searchable discovery/navigation and discoverable controls; visually inspect.
- [x] Windows distribution: executable-relative resources and writable user storage, synchronized version metadata, original logo/icon, complete curated asset/DLL/license staging, reproducible installer and portable archive.
- [x] Release QA: test fresh/continue/pause/settings/restart, isolated packaged runtime and installer, GL/science/save suite; capture curated screenshots and optimized benchmark evidence.
- [x] Release documentation: accurate README, data/asset notices, release notes, captured evidence and limitations; inspect source changes and distribution artifacts.

**Publication transaction:** Commit the reviewed source on the existing branch, create a new `v1.0.0` tag, push the branch/tag and fast-forward the default branch only after an ancestry check. Publish installer/ZIP/checksums without replacing any existing tag or release, then compare uploaded sizes/digests against local artifacts. The final delivery report records the resulting commit and release URL.

Each subsystem change receives relevant regression checks before advancing. Record actual verification and remaining limitations in the release report; keep development logs and private player data out of Git and distributions.
